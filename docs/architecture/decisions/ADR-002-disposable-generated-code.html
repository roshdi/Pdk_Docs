ADR-002: Generated Code Is Disposable

  • Status: Accepted
  • Date: 2026-07-17

Context

PDK must regenerate infrastructure as definitions and generators evolve. If developers edit generated files, regeneration can overwrite business behavior or require unreliable source merging.

Decision

Generated files must never be manually edited. They are disposable artifacts that can be deleted and recreated from definitions.

Developer-owned behavior must live in clearly separate partial classes, companion files, or explicit extension points that generation does not overwrite. Generated files must carry a recognizable marker where the file format permits.

Consequences

  • Generators may replace generated files without preserving local edits.
  • Generated and developer-owned file naming must be unambiguous.
  • New generated behavior must expose stable extension points where customization is expected.
  • Cleanup logic may delete only artifacts positively identified as generated.
  • Documentation must teach developers where custom behavior belongs.

Alternatives Considered

Preserve edits through text merging

Rejected because arbitrary source merging is fragile and makes output dependent on generation history.

Generate files only once

Rejected because created-once infrastructure cannot safely evolve with metadata or generator improvements.

Allow selected generated files to become developer-owned

Rejected as a default because ownership becomes ambiguous. Explicit companion templates may be created once, but those files must be identified as developer-owned from creation.
