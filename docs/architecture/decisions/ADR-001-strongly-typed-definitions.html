ADR-001: Strongly Typed Definitions Are the Structural Source of Truth

  • Status: Accepted
  • Date: 2026-07-17

Context

PDK needs one authoritative representation of application structure. Possible sources include C# definitions, external configuration files, domain-model reflection, and generated output. Multiple authoritative sources would create conflicts and make generation difficult to validate or reproduce.

Enterprise .NET teams benefit from compile-time feedback, refactoring support, code review, and discoverable APIs.

Decision

Strongly typed C# definitions are the source of truth for platform, service, entity, and capability structure.

PDK discovers these definitions, validates them, and builds a unified metadata model. Generators and runtime integration consume that metadata. External configuration may supply environment-specific values but does not redefine the structural model.

Consequences

  • Definition APIs require careful compatibility management.
  • Invalid structure can be diagnosed before generation.
  • IDE navigation, refactoring, and type checking improve the authoring experience.
  • Generators must not infer competing structural truth from generated files.
  • External formats may import or export metadata but remain derived representations.

Alternatives Considered

YAML or JSON as the primary source

Rejected because it provides weaker typing and refactoring support and creates a separate schema and tooling burden.

Domain classes as the primary source

Rejected because persistence-oriented domain types do not express the complete platform, service, security, generation, and UI model.

Hybrid authority

Rejected because conflicting sources require precedence rules and reduce determinism.
