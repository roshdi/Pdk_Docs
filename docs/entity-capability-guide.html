PDK Entity Feature and Capability Guide

PDK entities are structural metadata declared inside a ServiceDefinition. Profiles and capability interfaces describe reusable behavior that generators can apply consistently across entities.

[!NOTE] The definition API is available in the preview, but complete service and entity code generation is still under development.

Entity Model

The declaration hierarchy is:

PlatformDefinition
`-- ServiceDefinition
    `-- EntityDefinition
        |-- Table mapping
        |-- Entity profile
        |-- Explicit interfaces
        `-- Security and permissions

Capability Interfaces

Pdk.Core.Abstractions provides capability contracts for creation, modification, soft deletion, and optimistic concurrency:

  • ICreated
  • IModified
  • ISoftDelete
  • IOptimisticConcurrency

Applications define the properties and implementation used by generated entity types. For example:

using Pdk.Core.Abstractions;

public interface ICreatedEntity : ICreated
{
    DateTime CreatedOn { get; set; }

    void ICreated.SetCreated(IRequestContext context)
    {
        CreatedOn = DateTime.UtcNow;
    }
}

public interface ISoftDeleteEntity : ISoftDelete
{
    bool IsDeleted { get; set; }

    void ISoftDelete.SetDeleted(IRequestContext context)
    {
        IsDeleted = true;
    }

    void ISoftDelete.SetUndeleted(IRequestContext context)
    {
        IsDeleted = false;
    }
}

Production applications should obtain time, identity, and tenant information from IRequestContext services rather than directly using static system APIs.

Reusable Profiles

An EntityProfileDefinition groups interfaces that are commonly applied together:

using Pdk.Definitions.Entity;

public static class EntityProfiles
{
    public static readonly EntityProfileDefinition Audited =
        new EntityProfileDefinition()
            .Implements<ICreatedEntity>();

    public static readonly EntityProfileDefinition Aggregate =
        new EntityProfileDefinition()
            .Implements<
                ICreatedEntity,
                ISoftDeleteEntity>();
}

Profiles are application-defined shared metadata. Configure static profiles once and treat them as immutable after startup.

Optimistic Concurrency

PDK supports optimistic concurrency through the IOptimisticConcurrency capability. Any interface that extends IOptimisticConcurrency is detected automatically by the code generator — regardless of its name or the name of the concurrency property.

using Pdk.Core.Abstractions;

public interface IConcurrentEntity : IOptimisticConcurrency
{
    string Version { get; set; }

    void IOptimisticConcurrency.SetConcurrency(IRequestContext context)
    {
        // Version is managed by the database provider, not set manually.
    }
}

IConcurrentEntity is the default generated example. Developers can define their own interfaces with any name and any property:

public interface IOrderConcurrency : IOptimisticConcurrency
{
    string RowVersion { get; set; }
}

The generator detects any interface implementing IOptimisticConcurrency, finds the first settable property on it, and emits:

builder.HasRowVersion(e => e.PropertyName);

Provider Mapping

Each provider maps the native concurrency type to the property type (typically string) automatically:

Database Native Type Mechanism
SQL Server byte[] rowversion column via IsRowVersion()
PostgreSQL uint xmin system column via IsRowVersion()
Oracle long Trigger-incremented NUMBER via IsRowVersion() on long

Generated Code

When an entity implements any IOptimisticConcurrency-derived interface, the generated entity type configuration automatically emits:

builder.HasRowVersion(e => e.PropertyName);

where PropertyName is the first settable property declared on the interface.

Each Pdk.Data.* project provides:

  • A ValueConverter that converts between the property type and the provider's native concurrency type.
  • A HasRowVersion<TEntity>() extension method on EntityTypeBuilder<TEntity> that applies the converter automatically.

Services reference the appropriate Pdk.Data.* package for their database provider. The generated code calls HasRowVersion with the same API regardless of provider; the correct extension method resolves based on the referenced package.

Example

Declare a custom concurrency interface:

public interface IOrderConcurrency : IOptimisticConcurrency
{
    string RowVersion { get; set; }
}

Register an entity with this interface:

entities.Entity("Order")
    .Table("Orders")
    .Implements<IOrderConcurrency>();

The generated entity implements IOrderConcurrency with a string RowVersion property. The generated entity type configuration includes:

public override void Configure(EntityTypeBuilder<OrderEntity> builder)
{
    builder.ToTable("Orders", schemaName);
    ConfigureEntity(builder);
    builder.HasRowVersion(e => e.RowVersion);
}

When saving changes, EF Core throws DbUpdateConcurrencyException if the RowVersion value has changed since the entity was loaded.

The default IConcurrentEntity with string Version works the same way:

entities.Entity("Customer")
    .Table("Customers")
    .Implements<IConcurrentEntity>();

// Generated: builder.HasRowVersion(e => e.Version);

Capability Configuration

Capability interfaces can define EF Core property configuration through an optional static Configure method. The code generator detects this method and emits a call in the generated entity type configuration.

Convention

static void Configure<TEntity>(EntityTypeBuilder<TEntity> builder)
    where TEntity : class, IMyCapability
  • Name: Configure
  • Signature: generic, takes EntityTypeBuilder<TEntity>, constrained to where TEntity : class, I{CapabilityName}
  • Optional: only interfaces that need custom configuration implement it

Example

The default ICreatedEntity declares properties but does not configure string lengths. A developer can add configuration:

using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Metadata.Builders;
using Pdk.Core.Abstractions;

public interface ICreatedEntity : ICreated
{
    DateTime CreatedDate { get; set; }
    [AuthId] AuthId CreatedBy { get; set; }
    string CreatedByUserName { get; set; }

    void ICreated.SetCreated(IRequestContext context)
    {
        CreatedDate = context.Clock.Now;
        CreatedBy = context.Auth.CurrentUserId;
        CreatedByUserName = context.Auth.UserName;
    }

    static void Configure<TEntity>(EntityTypeBuilder<TEntity> builder)
        where TEntity : class, ICreatedEntity
    {
        builder.Property(e => e.CreatedByUserName).HasMaxLength(50);
    }
}

The generated entity type configuration calls this method automatically:

public override void Configure(EntityTypeBuilder<OrderEntity> builder)
{
    builder.ToTable(tableName, schemaName);
    ConfigureEntity(builder);
    ICreatedEntity.Configure(builder);
}

No manual partial class configuration is needed for standard capabilities.

Automatic vs Manual Configuration

Behavior Trigger Developer Action
HasRowVersion Any IOptimisticConcurrency interface None — just implement the interface
Configure method call Static Configure method on interface Write the method if property config is needed
Manual ConfigureEntity Non-generated partial class Hand-write in EntityTypeConfiguration.cs

HasRowVersion is automatic — the generator always emits it for concurrency interfaces. The Configure method is optional — only written when the capability needs property-level configuration like max length, precision, or default values.

Multiple Capabilities

An entity can implement multiple capabilities, each with its own Configure method. All are called in the generated configuration:

public override void Configure(EntityTypeBuilder<OrderEntity> builder)
{
    builder.ToTable(tableName, schemaName);
    ConfigureEntity(builder);
    builder.HasRowVersion(e => e.RowVersion);  // automatic
    IOrderConcurrency.Configure(builder);       // from Configure method
    ICreatedEntity.Configure(builder);          // from Configure method
}

Register Entities

Set a default profile for a service and override it where needed:

using Pdk.Definitions.Service;

public sealed class CustomerService : ServiceDefinition
{
    protected override void Configure()
    {
        Entities(entities =>
        {
            entities.DefaultProfile(EntityProfiles.Aggregate);

            entities.Entity("Customer")
                .Table("Customers");

            entities.Entity("CustomerNote")
                .Table("CustomerNotes")
                .Profile(EntityProfiles.Audited)
                .Implements<ISoftDeleteEntity>();

            entities.Entity("ImportRow")
                .OverrideImplements<ICreatedEntity, ISoftDeleteEntity>();
        });
    }
}

Use:

  • DefaultProfile(...) for entities subsequently added by the builder.
  • Profile(...) to select a profile for one entity.
  • Implements<T>() to add explicit interfaces.
  • OverrideImplements<T>() to replace explicitly configured interfaces.
  • Table(...) to set the persistence table name.

Duplicate entity names are compared case-insensitively and produce diagnostic PDK201.

DbContext Generation

PDK generates a {ServiceName}DbContext in the service's Core project. The context extends DbContextBase from Pdk.Data and includes DbSet properties for each entity.

Generated Files

File Purpose
{ServiceName}DbContext.g.cs Auto-generated: constructor, OnModelCreating, DbSet properties
{ServiceName}DbContext.cs Developer-editable scaffold (created once, not overwritten)

Generated DbContext

using Microsoft.EntityFrameworkCore;
using Pdk.Data;
using PdkSample.Sales.Customer.Core.Entities;
using PdkSample.Sales.Customer.Core.EntityConfigurations;

namespace PdkSample.Sales.Customer.Core;

public partial class CustomerDbContext : DbContextBase
{
    public CustomerDbContext(DbContextOptions<CustomerDbContext> options)
        : base(options)
    {
        DefaultSchema = "Customer";
        MoreOptions(options);
    }

    partial void MoreOptions(DbContextOptions options);

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        base.OnModelCreating(modelBuilder);
        modelBuilder.ApplyConfiguration(new CustomerEntityTypeConfiguration(DefaultSchema));
        modelBuilder.ApplyConfiguration(new CustomerNoteEntityTypeConfiguration(DefaultSchema));
        MoreOnModelCreating(modelBuilder);
    }

    partial void MoreOnModelCreating(ModelBuilder modelBuilder);

    public DbSet<CustomerEntity> Customers => Set<CustomerEntity>();
    public DbSet<CustomerNoteEntity> CustomerNotes => Set<CustomerNoteEntity>();
}

Extension Points

Partial Method Purpose
MoreOptions(DbContextOptions options) Configure provider-specific options or change DefaultSchema
MoreOnModelCreating(ModelBuilder modelBuilder) Add indexes, constraints, seed data, or additional configuration

The DefaultSchema property defaults to the service name. Change it in MoreOptions if needed:

public partial class CustomerDbContext
{
    partial void MoreOptions(DbContextOptions options)
    {
        DefaultSchema = "sales";
    }
}

DbSet Naming

DbSet property names are pluralized from the entity name: Customer → Customers, Order → Orders, CustomerNote → CustomerNotes.

Multiple Entities

Each entity registered in the service definition gets:

  • A DbSet<TEntity> property on the DbContext
  • An ApplyConfiguration call in OnModelCreating
  • Its own EntityTypeConfiguration class

Entity Security

Security capabilities implement ISecurity and declare supported permissions and scopes:

using Pdk.Core.Security;

public interface IBasicSecurity : ISecurity
{
    static void ISecurity.ConfigurePermissions(PermissionBuilder permissions)
    {
        permissions.Read();
        permissions.Create().ImpliesRead();
        permissions.Update().ImpliesRead();
        permissions.Delete().ImpliesRead();
    }

    static SecurityScopeDefinition[] ISecurity.GetAvailableScopes() =>
    [
        new(SecurityScopeDefinition.DenyAllScopeId, "Deny all"),
        new(SecurityScopeDefinition.AllowAllScopeId, "Allow all")
    ];
}

Associate the capability and configure entity-specific permission groups:

entities.Entity("Customer")
    .HasSecurity<IBasicSecurity>(permissions =>
    {
        var standard = permissions.Default();
        standard.Read();
        standard.Create().ImpliesRead();
        standard.Update().ImpliesRead();
        standard.Delete().ImpliesRead();

        permissions.Group("Workflow")
            .Add("Approve")
            .ImpliesRead();
    });

Capability permissions describe what a security model supports. Entity permission groups describe the permissions generated for a specific entity.

See the Security Capability Guide for the broader security model. Some examples in that guide may evolve while the preview APIs are being consolidated.

Register the Service

Services belong to a platform:

public sealed class SalesPlatform : PlatformDefinition
{
    public override void Configure()
    {
        Platform(platform => platform
            .Name("Sales")
            .RootNamespace("Sales"));

        Services(services =>
        {
            services.Add<CustomerService>();
        });
    }
}

Registering the same service type twice produces diagnostic PDK101.
